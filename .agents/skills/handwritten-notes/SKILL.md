# 手写笔记整理

## 交付形式

- 要按 `学科/具体科目/notes/` 归档，目录和文件名采用英文小写及连字符，正文使用中文。例如 `mathematics/mathematical-analysis-i/notes/01-02-sets-and-suprema.tex`。
- 要按教材章节命名为 `章号-节号-英文主题`，将可编辑的 `.tex` 与同名 `.pdf` 放在一起。科目需要区分学期时，可使用 `-i`、`-ii` 等后缀。
- 要从仓库根目录的 [template.tex](../../../template.tex) 起步，标题区保留标题、署名 `Yuchen Zhang` 和固定日期。日期含义要明确：已知课堂日期时使用课堂日期，按整理时间记录时注明“整理日期”。

## 阅读与核查

- 要先确认课程、章节和本次整理范围，再逐页阅读原稿。HEIC 等格式可先转为临时 PNG；难辨的公式、上下标、区间端点和涂改处要放大核对。
- 要结合上下文判断笔误，检查定义的适用条件、量词、不等号方向、边界情形及证明的完整性。影响数学含义且无法可靠辨认的内容，要向用户确认，其余部分可先整理。
- 要保留原稿的主要知识点和例题，修正确定的错误，补齐理解与推理所必需的条件和步骤。教材章节信息用于定位内容，教材原文的核对以实际取得的材料为依据。

## 正文组织

- 要按知识逻辑安排小节，以“定义”“命题／定理”“例题”和“证明”明确区分内容。定义与定理保持准确简洁，证明紧跟对应命题或例题。
- 要直接呈现整理后的知识内容。标题区保持简洁，编辑过程、教材定位和纠错说明放在交付回复中；例题以题目和完整解答构成，解释融入必要的推理步骤。
- 要使用适量的解释帮助读者衔接关键步骤，沿用原稿的符号并统一其含义。内容的密度和解释程度要随用户反馈调整。
- 要以 [已确认的第一篇笔记](../../../mathematics/mathematical-analysis-i/notes/01-02-sets-and-suprema.tex) 作为格式参考，按新内容安排分页和层级。

## 编译与检查

- 要沿用模板的 **LuaLaTeX + CTeX + Fandol** 配置、编译器提示和引擎检查，让中文字体及 Unicode 映射随 PDF 嵌入。
- 要在临时构建目录编译，含交叉引用或书签时按编译提示再次运行；将确认后的 PDF 放回笔记目录。模板有改动时，也要单独编译验证。
- 要实际渲染 PDF，逐页检查中文、数学公式、分页、行宽和证明结束符，并抽查中文文字提取。遇到阅读器差异时，要结合字体映射和渲染结果定位原因。
- 要在交付回复中给出源文件和 PDF 的入口，简述重要纠错、验证结果及确需确认的问题。用户确认的通用格式调整要同步到模板或本 skill 的相应位置。

## 博客 metadata

- 要沿用模板顶部 `% halo:begin` 至 `% halo:end` 的 JSON 注释块，所有字段保持齐全；新笔记默认 `publish: false`，用户确定纳入自动发布后设置为 `true`。注释仅控制网页发布，PDF 标题仍由 `\title` 控制。
- 要从 [受控词表](../../../publish/notes.json) 选择 `course`、`categories` 和 `tags` 的英文键；分类恰好一个，标签至少一个且唯一。新增课程或词条要统一修改词表，分类和标签的中文显示名称要与 Halo 已有项一致。
- 要将 `section` 写为无前导零的教材节号（如 `1.2`），文件名使用两位章号与节号（如 `01-02-sets-and-suprema.tex`）。
- 要将 `title` 精确写为“词表中的课程名 + 节号 + 中文冒号 + LaTeX 纯文本标题”，例如 `数学分析（一）1.2：数集与确界原理`。文章 slug 由课程键和文件名自动生成，已发布笔记的路径要保持稳定。
- 要填写简短、单行的 `excerpt`，并在交付前运行 `python3 scripts/publish_notes.py --preview`，使 metadata、路径和正文转换全部通过校验。完整约定见 [发布说明](../../../publish/README.md)。
